# ナンプレ練習帳

白黒の、自分用のナンプレ練習Webアプリです。数字・候補入力、盤面への手書き、印刷、論理解法の記録に対応します。外部ライブラリ、通信、アカウントは不要です。

公開版： https://jankyjanky0920.github.io/mypuzzle/

ソース： https://github.com/jankyjanky0920/mypuzzle

新9種類もアナログ回答はABCDです。**初期収録106問（通常63問・最上難易度43問）**。種類・難易度ごとに未着手の問題を選び、不足時はブラウザ内で新しい問題を生成・検証してから出題します。手動の「未着手の問題を1問生成・検証」でも補充できます。

「次の一手」は最初の数字確定で終了します。その後の完成盤面の一意性は条件にしません。実際に、完成盤面が複数ある問題も収録しています。他の18種類は完成盤面が一意であることを確認しています。

## ナンプレテストモード

制限時間は120分。ナンプレ系の種類から最大20種類を選び、20種類未満なら全種類を出題します。スタンダードは必須で2問、次の一手は選ばれた場合4問、ほかは現在各1問です。現在は19種類・23問。開始時に選んだ通常／最上難易度とデジタル／アナログで全問を出題します。同じテスト内で問題は重複しません。未着手の問題が足りない場合は必要な数を生成・検証し、準備が完了してから120分の計測を始めます。

- 残り時間は開始時刻と締切時刻から計算し、問題一覧・設定・ホームへの移動・ブラウザを閉じている間も進みます。締切後に開くと時間切れとして採点します。
- 問題は自由に行き来でき、数字・候補・手書き・回答・解法記録と記録の下書きを問題ごとに自動保存します。途中のテストはホームから再開できます。
- テスト中はヒント・模範解答・候補の自動記入・個別の正誤判定を使いません。回答ボタンは保存のみです。モードは開始時に決定します。
- 終了・時間切れで回答を固定し、各問1点でまとめて採点します。デジタルは全盤面、アナログはABCDの4マスすべて、次の一手は場所と数字の両方が合うことを正解条件にします。
- 結果は通常練習の履歴と分けて保存します。「通常練習で復習」は回答・手書き・記録を新しい練習へコピーし、提出済みの回答を保持します。

種類の登録は `family: 'number-place'`、`testCount`、`testRequired` を持ちます。今後加えるナンプレ以外の種類は別の `family` を使い、このテストの候補に入りません。出題数を変更しても保存済みテストの構成と結果は変えません。

## 操作

- ランダム：問題の種類で「ランダム（すべての種類）」を選び、難易度とモードを指定します。未着手の問題がある種類を均等に選び、その中から1問をランダムに出題します。
- 次のランダム問題：同じ難易度・現在のモードで続けられます。未着手の問題がなくなった場合は、新しい問題を生成・検証して出題します。再読込後もランダム選択での練習を続けられます。
- デジタル：空欄を選んで数字を入力。同じ数字をもう一度押すと消せます。6×6は1〜6、8×8は1〜8、通常の9×9は1〜9、抜け番は0〜9です。抜け番の0は数字であり、空欄ではありません。
- 次の一手のデジタル回答：マスを選び数字を入力し、「選んだ一手を判定」。残りのマスは埋める必要がありません。
- 候補：小さい数字でメモできます。メモと論理エンジン内の候補は独立しています。
- ペン：盤面に直接書けます。文字の自動認識・数字入力への変換はしません。
- 消しゴム：線に触れると、そのひと筆を消します。
- 指では書かない：ペンで書き、指ではスクロールします。オフにすると指でも書けます。
- 戻す・やり直す：数字、候補、手書き、記録を操作単位で戻せます。開いている間の45操作を保持します。
- アナログ：手書き・紙で考えて、指定4マスの数字、または次の一手の座標と数字を提出します。全盤面の読取はしません。
- ヒント：場所→解法→理由→結論の順で開きます。理由以降は解答の数字を含むことがあります。
- アナログのヒント：必要に応じて確定数字を転記できます。次の一手のヒントは開始盤面から最初の数字確定までを扱います。
- 記録：使った解法、対象マス、理由・手順を残せます。模範解答は別途開きます。
- 印刷：初期数字・追加ルール・回答用の表示を印刷します。着せ替えは3つの区切り図も付けます。入力済み数字・手書きは印刷しません。

キーボード：0〜9＝その種類で使う数字、矢印＝移動、N＝候補、P＝ペン、E＝消しゴム、Delete / Backspace＝削除、Ctrl/⌘+Z＝戻す、Ctrl/⌘+Shift+Z＝やり直す。

タブレット実機のスタイラスの書き味は未検証です。スマートフォン・パソコンでは通常の数字・候補入力が使えます。

## 保存と公開

進捗、手書き、解法記録、回答、時間を同じ端末・同じブラウザのlocalStorageに保存します。旧版の問題IDと保存形式を維持しています。生成した問題と検証済み手順も同じ端末に保存します。問題を替えてもホームの履歴から戻れます。デジタル・アナログの完了判定は独立しています。

直前の保存を予備として保持します。本体を読めない場合は予備から復旧し、どちらも読めない場合は空のデータで上書きせず保護します。保存に失敗した場合は画面に表示します。設定からJSONバックアップを保存・読込できます。自動同期はありません。生成問題の保存量には上限があり、古い使用済みの生成問題とその練習・終了済みテストの記録は整理することがあります。開いている練習と進行中のテスト、そのテストの準備中に確保した問題は保護します。必要なら古い未着手の生成問題も整理します。

GitHubへ送るのはアプリと検証済み問題だけです。練習履歴・回答・手書きは送信しません。GitHub Pagesは `main` の `/docs` を配信します。更新後は固定の公開URLを同じブラウザで開いてください。

ローカル版は `sudoku-practice.html` または `dist/index.html` をブラウザで開けます。ローカル版、別の試用URL、公開URLはそれぞれ保存領域が違います。移す場合は元の画面でバックアップを書き出し、移行先で読み込んでください。iPadのファイルプレビューではHTML内のプログラムが動かないことがあります。

## 問題の品質条件

- 次の一手以外は、全制約を含む厳密探索が完了し、解が1つであることを確認します。探索上限で中断した問題は採用しません。
- 解法エンジンは完成解を受け取りません。各手の構造証明を、解法発見処理とは別の検証関数で確認します。
- 通常は基本確定、候補のロック、ペア・トリプル。スタンダード・次の一手ではX-Wingも使用します。最上難易度は通常解法で止まり、Wing等の上位解法で解けることが条件です。
- AIC / XY-Chainは最大7リンク。仮置き分岐、長い背理法、Forcing Net、総当たりを解説に使用しません。一意性検査の探索とは分離しています。
- 次の一手は、最初の数字確定までの途中手順を検証し、6方針で同じ1マス・同じ数字になることを検査します。確定が見つかった後は論理手順を延長しません。
- ABCDは12の解答順で各マスの確定順位が初期空欄の80%以上になることを検査します。4合体は各所属盤面の空欄に対する順位で調べます。さらに3つのABCD優先方針で、4マスが揃うまでに全体の空欄の80%以上を確定する必要があることを検査します。
- スタンダードのABCDは基準手順の最後の4マスです。追加種類では、終盤性と種類別の配置条件を満たすマスから選びます。
- 12方針は標準順、逆順、同等の選択肢に周期的に寄り道する10順です。すべての人間の解答順・すべての別解法を網羅する保証ではありません。次の一手も、採用した解法と探索範囲で最初の確定を検査します。

難易度はアプリ内の解法基準です。利用できる解法の検出には探索上限があります。

## ブラウザでの作問

Web Workerで作問するため、生成中もキャンセルできます。全19種類・両難易度に対応します。検証済みの問題から、ルールを保つ数字の置換・回転・反転を行い、候補によっては初期数字を再削減します。論理手順・難易度・一意性・ABCDを再計算し、元の証明を流用しません。種類に応じて新しい完成盤面・追加条件からも作問します。着せ替え・4合体など、実行時間の大きい種類は検証済みの構造を基に変形します。

問題の指紋で、保存中・使用済みの同じ問題を避けます。生成結果はWorker内と画面側で再検証してから保存します。試行・時間の上限までに品質条件を満たせなければ、その旨を表示して再試行できます。条件を下げた問題や未検証の問題は出題しません。

## 開発

Node.js 20以降。パッケージの追加インストールは不要です。

```sh
npm run build
npm test
```

- `src/engine.js`：9×9の論理、厳密探索、証明検証、作問。
- `src/extra-rules.js`：和・ポーカー役・偶数ブロック・偶数はさみ・ヒット数の候補支持、証明検証、完成条件。
- `src/variant-engine.js`：任意形状・重複区画、短い直線の重複禁止、数字制限・大小・差・四捨五入の論理・証明・厳密探索。短い直線では各数字の出現を必須とせず、隠れたシングルなどの根拠と区別します。
- `src/puzzle-types.js`：種類・分類・テスト出題数、座標、各種類の制約定義、未着手優先のランダム選択。
- `src/board-view.js`：盤面の境界線・追加記号、正六角形の配置、着せ替え図、印刷SVG。
- `src/test-mode.js` / `src/test-ui.js`：テストの選択・締切・採点・保存検証と画面操作。
- `src/app.js` / `src/storage.js`：入力・手書き・判定・記録・保存。
- `src/puzzles.json` / `src/variant-puzzles.json`：検証済みの問題と証明付き手順。
- `src/generator.js` / `src/generation-worker.js` / `src/runtime-generation.js`：作問・独立検証・Worker実行・キャンセル。
- `src/inventory.js`：未着手在庫、使用済み記録、保存容量と保護対象の整理。
- `src/generation-seeds.json`：偶数ブロックの完成盤面とヒット盤面の作問素材。素材の完成解を論理解法には渡さない。
- `src/generation-geometry.js`：共通の幾何学的な盤面作成。
- `scripts/generate-pool.js`：スタンダードの作問。
- `scripts/generate-variants.js` / `scripts/variant-geometry.js`：追加種類の作問。完成解を作り、数字を削り、一意性・論理解法・難易度・回答位置を検査して採用。
- `scripts/generate-more.js`：新9種類の作問。`KIND=sizeParity|missing|poker|evenBlocks|arrow|mount|evenSandwich|symmetry|hit` と `NORMAL`、`EXTREME`、`SEED`、`ATTEMPTS`、`OUT` を指定できる。
- `scripts/merge-variants.js`：独立して作った問題集合をまとめ、現在のエンジンで再検証。
- `scripts/build.js`：すべてを単一HTMLにまとめ、`docs/index.html`、`dist/index.html`、`sudoku-practice.html`へ出力。
- `tests/`：論理・形状・一意性・難易度・ABCD・保存互換性・配布HTMLの回帰検査。

作問は `KIND=next|shuriken|costume|consecutive|diagonal|inequality|oneOrEight|honeycomb|rounding`、`NORMAL`、`EXTREME`、`SEED`、`ATTEMPTS`、`OUT` で対象・目標数・試行上限・出力先を指定できます。`npm run generate:variants` は収録済みの数を考慮して不足分を試作します。着せ替えは、通常向けには近い区切りと一般のラテン方陣、最上難易度向けには別々の区切りを探索します。`COSTUME_NEAR=0|1`、`COSTUME_RANDOM_LATIN=0|1` でも指定できます。作問に時間がかかり、試行上限までに目標数へ達しない場合があります。

複数の生成処理を同時に動かす場合は別々の `OUT` を指定し、終了後に `node scripts/merge-variants.js 出力ファイル...` で統合してください。問題を追加したらビルドとテストを実行してから公開します。
