# ナンプレ練習帳

白黒の、自分用のナンプレ練習Webアプリです。数字・候補入力、盤面への手書き、印刷、論理解法の記録に対応します。外部ライブラリ、通信、アカウントは不要です。

公開版： https://jankyjanky0920.github.io/mypuzzle/

ソース： https://github.com/jankyjanky0920/mypuzzle

## 収録する5種類

| 種類 | ルール・回答 | 通常 | 最上難易度 |
| --- | --- | ---: | ---: |
| スタンダードナンプレ | 各行・列・3×3ブロックに1〜9。アナログはABCD。 | 8 | 4 |
| 次の一手ナンプレ | 最初に論理で数字を確定できる1マスと数字を答える。アナログは列A〜I・行J〜R・数字の順で `AJ1`。 | 4 | 2 |
| 4合体ミニ幾何学ナンプレ | 四つの6×6。各盤の行・列・6マスの変形ブロックに1〜6。角の2×3ブロックを共有し、全体は90度回転対称、中央1マスは黒。ABCDは各盤1マス、共有部分以外。 | 3 | 2 |
| 着せ替えナンプレ | 6×6の行・列と、別掲する3種類すべてのブロックで1〜6を成立させる。アナログはABCD。 | 3 | 2 |
| 一つ違いナンプレ | 9×9の基本ルールに加え、二重線で接する数字の差は1。それ以外のタテヨコに隣り合う数字の差は2以上。アナログはABCD。 | 3 | 3 |

**計34問**。種類・難易度ごとに未着手の問題から選び、一巡した場合は再挑戦を明示します。ブラウザで未検証の問題を即時生成しません。生成器はソースに含まれています。

「次の一手」は最初の数字確定で終了します。その後の完成盤面の一意性は条件にしません。実際に、完成盤面が複数ある問題も収録しています。他の4種類は完成盤面が一意であることを確認しています。

## 操作

- デジタル：空欄を選んで数字を入力。同じ数字をもう一度押すと消せます。6×6は1〜6、9×9は1〜9です。
- 次の一手のデジタル回答：マスを選び数字を入力し、「選んだ一手を判定」。残りのマスは埋める必要がありません。
- 候補：小さい数字でメモできます。メモと論理エンジン内の候補は独立しています。
- ペン：盤面に直接書けます。文字の自動認識・数字入力への変換はしません。
- 消しゴム：線に触れると、そのひと筆を消します。
- 指では書かない：ペンで書き、指ではスクロールします。オフにすると指でも書けます。
- 戻す・やり直す：数字、候補、手書き、記録を操作単位で戻せます。開いている間の45操作を保持します。
- アナログ：手書き・紙で考えて、指定4マスの数字、または次の一手の座標と数字を提出します。全盤面の読取はしません。
- ヒント：場所→解法→理由→結論の順で開きます。理由以降は解答の数字を含むことがあります。
- アナログのヒント：必要に応じて確定数字を転記できます。次の一手のヒントは開始盤面から最初の数字確定までを扱います。
- 記録：使った解法、対象マス、理由・手順を残せます。模範解答は別途開きます。
- 印刷：初期数字・追加ルール・回答用の表示を印刷します。着せ替えは3つの区切り図も付けます。入力済み数字・手書きは印刷しません。

キーボード：1〜9＝数字（6×6では6まで）、矢印＝移動、N＝候補、P＝ペン、E＝消しゴム、Delete / Backspace＝削除、Ctrl/⌘+Z＝戻す、Ctrl/⌘+Shift+Z＝やり直す。

タブレット実機のスタイラスの書き味は未検証です。スマートフォン・パソコンでは通常の数字・候補入力が使えます。

## 保存と公開

進捗、手書き、解法記録、回答、時間を同じ端末・同じブラウザのlocalStorageに保存します。旧版のスタンダードナンプレ12問のIDと保存形式を維持しています。問題を替えてもホームの履歴から戻れます。デジタル・アナログの完了判定は独立しています。

直前の保存を予備として保持します。本体を読めない場合は予備から復旧し、どちらも読めない場合は空のデータで上書きせず保護します。保存に失敗した場合は画面に表示します。設定からJSONバックアップを保存・読込できます。自動同期はありません。

GitHubへ送るのはアプリと検証済み問題だけです。練習履歴・回答・手書きは送信しません。GitHub Pagesは `main` の `/docs` を配信します。更新後は固定の公開URLを同じブラウザで開いてください。

ローカル版は `sudoku-practice.html` または `dist/index.html` をブラウザで開けます。ローカル版、別の試用URL、公開URLはそれぞれ保存領域が違います。移す場合は元の画面でバックアップを書き出し、移行先で読み込んでください。iPadのファイルプレビューではHTML内のプログラムが動かないことがあります。

## 問題の品質条件

- 次の一手以外は、全制約を含む厳密探索が完了し、解が1つであることを確認します。探索上限で中断した問題は採用しません。
- 解法エンジンは完成解を受け取りません。各手の構造証明を、解法発見処理とは別の検証関数で確認します。
- 通常は基本確定、候補のロック、ペア・トリプル、9×9ではX-Wingまで。最上難易度は通常解法で止まり、Wing等の上位解法で解けることが条件です。
- AIC / XY-Chainは最大7リンク。仮置き分岐、長い背理法、Forcing Net、総当たりを解説に使用しません。一意性検査の探索とは分離しています。
- 次の一手は、最初の数字確定までの途中手順を検証し、6方針で同じ1マス・同じ数字になることを検査します。確定が見つかった後は論理手順を延長しません。
- ABCDは12の解答順で各マスの確定順位が初期空欄の80%以上になることを検査します。4合体は各所属盤面の空欄に対する順位で調べます。さらに3つのABCD優先方針で、4マスが揃うまでに全体の空欄の80%以上を確定する必要があることを検査します。
- スタンダードのABCDは基準手順の最後の4マスです。追加種類では、終盤性と種類別の配置条件を満たすマスから選びます。
- 12方針は標準順、逆順、同等の選択肢に周期的に寄り道する10順です。すべての人間の解答順・すべての別解法を網羅する保証ではありません。次の一手も、採用した解法と探索範囲で最初の確定を検査します。

難易度はアプリ内の解法基準です。利用できる解法の検出には探索上限があります。

## 開発

Node.js 20以降。パッケージの追加インストールは不要です。

```sh
npm run build
npm test
```

- `src/engine.js`：9×9の論理、厳密探索、証明検証、作問。
- `src/variant-engine.js`：任意形状・重複する区画と、隣接する数字の差の論理・証明・厳密探索。
- `src/puzzle-types.js`：種類、座標、6×6・4合体の制約定義。
- `src/board-view.js`：盤面の境界線、二重線、着せ替え図、印刷SVG。
- `src/app.js` / `src/storage.js`：入力・手書き・判定・記録・保存。
- `src/puzzles.json` / `src/variant-puzzles.json`：検証済みの問題と証明付き手順。
- `scripts/generate-pool.js`：スタンダードの作問。
- `scripts/generate-variants.js` / `scripts/variant-geometry.js`：追加種類の作問。完成解を作り、数字を削り、一意性・論理解法・難易度・回答位置を検査して採用。
- `scripts/merge-variants.js`：独立して作った問題集合をまとめ、現在のエンジンで再検証。
- `scripts/build.js`：すべてを単一HTMLにまとめ、`docs/index.html`、`dist/index.html`、`sudoku-practice.html`へ出力。
- `tests/`：論理・形状・一意性・難易度・ABCD・保存互換性・配布HTMLの回帰検査。

作問は `KIND=next|shuriken|costume|consecutive`、`NORMAL`、`EXTREME`、`SEED`、`ATTEMPTS`、`OUT` で対象・目標数・試行上限・出力先を指定できます。`npm run generate:variants` は収録済みの数を考慮して不足分を試作します。着せ替えは、通常向けには近い区切りと一般のラテン方陣、最上難易度向けには別々の区切りを探索します。`COSTUME_NEAR=0|1`、`COSTUME_RANDOM_LATIN=0|1` でも指定できます。作問に時間がかかり、試行上限までに目標数へ達しない場合があります。

複数の生成処理を同時に動かす場合は別々の `OUT` を指定し、終了後に `node scripts/merge-variants.js 出力ファイル...` で統合してください。問題を追加したらビルドとテストを実行してから公開します。
